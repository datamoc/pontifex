# Pontifex biome assets: developer guide

326 static SVG assets for the Pontifex bridge game (side view, 2D, PixiJS), grouped into biomes. Generated by code (`npm run gen:biomes`), so they can be tuned or extended without redrawing. The former base set (car, jeep, truck, clouds, tree, bush, rocks, explosion, flame) now lives in `common` (`src/gen/biomes/base.ts`); `npm run gen:pontifex` is an alias of `gen:biomes`. Its files moved from `drawings/pontifex/<name>.svg` to `drawings/pontifex/biomes/common/<name>.svg` (content unchanged) and its manifest entries are now `common/<name>` in `biomes/manifest.json`.

## Output layout

```
drawings/pontifex/biomes/
  manifest.json              one entry per asset, key "<biome>/<name>"
  <biome>/<name>.svg
  sheet-<biome>.png          contact sheet for a quick visual check
```

| biome | assets | content |
|---|---|---|

| `cyberpunk` | 21 | neon towers, megacorp tower, container stack, tech pagoda, billboards; hover-car, maglev, drone, armoured truck, bus; rain overlay |

## Manifest fields

```jsonc
"common/wind_turbine": {
  "file": "common/wind_turbine.svg", "biome": "common", "category": "prop",
  "width": 130, "height": 178,
  "anchor": [0.5, 1],              // normalised origin (default bottom-centre)
  "pivots": { "rotor": [65, 62] }, // animated group -> pivot in SVG units
  "tile": true,                    // backgrounds / overlays: repeat horizontally
  // vehicles only:
  "wheelbase": 98, "foot": 1, "wheels": ["wheel-rear", "wheel-front"],
  "hood": { "pivot": [78, 20], "openAngle": -40 },  // car, jeep: rotate group #hood around pivot to open it
  "tints": { "paint": "#f59e0b" },                  // recolourable roles and their default colour
  "rig": { ... }                                    // cyclist only, see "Rigs"
}
```

Categories: `person`, `frame` (baked animation frame: filter these out of menus), `cloud`, `effect` (explosion, flame), `building`, `prop`, `vegetation`, `vehicle`, `boat`, `fauna`, `rock`, `terrain`, `pillar`, `background`, `overlay`.

## Conventions (same as the base set)

- **Static SVG only**: no `<script>`, `<filter>`, `<text>`, `<image>`, fonts. The generator throws if one appears. "Glow" (cyberpunk) is faked with stacked translucent strokes (`glow()` in `biomes/common.ts`).
- Flat style: outline `#1e293b` 2 units, round joins, a side shadow and a highlight.
- `width`/`height` equal the `viewBox`. Scale per asset is up to the game (vehicles: `0.6 * vehicle width / wheelbase`, as for the base set).
- **Anchors**: scenery bottom-centre `[0.5, 1]`; clouds, overlays `[0, 0]`; backgrounds `[0, 1]`; flying birds, drone, floating ad, tumbleweed, aurora-like items centred; boats `[0.5, ~0.75]` so the hull sits in the water; `cable_car_cabin`, `liana`, `icicles`, `pier` hang from the top `[0.5, 0]`.
- **Vehicles** face right. Wheels are groups `wheel-rear`, `wheel-front` (`wheel-mid`, then `wheel-1...` when there are more), drawn around their centre so they can rotate. Body is in `body`. Non-wheeled vehicles (`hover_car`, `maglev`, `drone`) have no `wheels` entry.
- **Backgrounds** are 800 wide and **seamless when tiled**: place copies at `x = 0, 800, 1600...`. Use a different scroll speed per layer (`far` slowest). Suggested parallax factors: far 0.2, mid 0.4, near 0.7.

## Recolourable parts (tints)

Parts the game may recolour carry `data-tint="<role>"` in the SVG. The manifest lists, per asset, `tints: { role: defaultColour }` (48 assets have some). If the element has a fill the fill is replaced, otherwise (stroked tubes, for example the bike frame) the stroke. Shadows and highlights are separate translucent shapes without a tint, so they keep working on any colour. Outlines are never tinted.

| role | where | notes |
|---|---|---|
| `paint` | body of every vehicle (car, jeep, truck cab, tram, buses, vans, tractor, hover-car, bicycle frame...), car and jeep `hood` | main colour |
| `stripe` | side stripe of box vehicles, van label line | secondary colour |
| `cargo` | truck box | |
| `sign` | van side panel | |
| `cloth-top`, `cloth-bottom`, `skin`, `helmet`, `hair`, `shoe` | cyclist, walkers | shirt and sleeves, trousers or skirt, skin, helmet, hair, shoes |
| `wall`, `roof`, `door` | every `house()` building (euro city, country, mountain, harbour...) | |
| `foliage`, `foliage-dark`, `foliage-light` | round trees (and fir trees: `foliage`, `foliage-light`) | the three roles are one family: use `tintFamily("foliage", base)` |
| `trunk` | trees | |

Runtime helper (dependency free, copy it into Pontifex): `src/runtime/tint.ts`

```ts
import { applyTints, listTints, tintFamily, shadeColor } from "./tint";

const svg = await (await fetch("/art/biomes/common/car.svg")).text();
const red = applyTints(svg, { paint: "#dc2626" });           // new SVG string
const tex = await Assets.load({ src: `data:image/svg+xml;utf8,${encodeURIComponent(red)}`, data: { resolution: 2 } });
// foliage: tintFamily("foliage", "#ea580c") -> { foliage, foliage-dark, foliage-light }
```

Rasterise once per colour combination and cache the texture (key = asset + sorted tints). Do not tint per frame. To add a tint to a new asset, pass `tint: "role"` in the options of `shape()` (`src/gen/kit.ts`); the manifest picks it up on regeneration. Keep the role vocabulary above rather than inventing near-duplicates.

## Rigs: the cyclist

`common/cyclist` (84 x 78, tyres on the last row, facing right) is a vehicle (`wheelbase`, `wheels`) with a rider whose legs follow the pedals. Groups:

| group | content | pivot (in manifest `pivots`) |
|---|---|---|
| `wheel-rear`, `wheel-front` | spoked wheels | their centre (rotate with speed) |
| `crank` | both crank arms and pedals | bottom bracket |
| `leg-near`, `leg-far` | thigh; **contains** the nested `shin-near` / `shin-far` (shin + shoe) | hip |
| `shin-near`, `shin-far` | rotate inside their thigh | knee, in the base pose |
| `torso`, `arm-near`, `head`, `bike` | static | |

Three ways to animate it, from easiest:

1. **Baked frames**: `cyclist_f0` ... `cyclist_f7` are the same asset at crank angles 0, 45 ... 315 degrees. Cycle through them as a sprite animation (about 8 frames per crank turn) and rotate nothing else. Wheels are baked in these frames; spin them by swapping to the full asset, or accept static wheels at this size.
2. **Rig**: set `crank.rotation` and pose both legs with `legPose` from `src/runtime/rig.ts` (the same two-bone solver the generator uses to bake the frames):

```ts
import { legPose } from "./rig";
const rig = manifest["common/cyclist"].rig.legs;     // hip, bb, crank, thigh, shin, baseAngle
function pedal(deg: number) {
  crank.rotation = deg - rig.baseAngle;                  // degrees, around pivots.crank
  const n = legPose(rig, deg, 0), f = legPose(rig, deg, 180);
  legNear.rotation = n.thigh;  shinNear.rotation = n.shin;   // around hip / knee pivots
  legFar.rotation = f.thigh;   shinFar.rotation = f.shin;
}
```
(angles in degrees: convert to radians for PixiJS; set each group's pivot from `pivots` and add the pivot position back so it rotates in place). The y axis points down, 0 degrees = crank pointing forward, 90 = down.
3. **Your own IK**: `rig.legs` gives hip, bottom bracket, crank length, thigh and shin lengths.

`common/bicycle` is the same bike without a rider (parked bikes, `crank` and wheels still rotate). A rider's clothes and the frame are tintable (see above), so a few colour combinations give many different cyclists.

## Walkers (people)

`common/walker_<preset>` (44 x 70, facing right, feet on the last row, anchor bottom-centre) are rigged pedestrians with a walk cycle. 12 presets are generated; `src/gen/biomes/people.ts` builds any other from options:

| option | values | effect |
|---|---|---|
| `build` | `slim`, `average`, `broad` | torso thickness |
| `chest` | 0 (flat) ... 1 (full) | chest bump on the top |
| `hips` | 0 ... 1 | pelvis width, skirt width |
| `hair` | 0 bald, ~0.1 buzz, 0.3 short, 0.55 shoulder, 0.8 mid-back, 1 waist | hair length |
| `hairStyle` | `loose`, `ponytail`, `bun` | |
| `lower` | `{ kind: "trousers", length }` 0.35 shorts, 0.6 knee, 0.8 capri, 1 full | trousers, bare legs below the hem |
| | `{ kind: "skirt", length, flare? }` 0.15 mini, 0.35 knee, 0.6 midi, 1 maxi | skirt, bare legs below the hem |
| `sleeve` | 0 tank, 0.45 t-shirt, 1 long sleeve | share of the arm covered |
| `colors` | `skin`, `hair`, `top`, `bottom`, `shoe` | default colours (see tints) |

Presets: `man_short_hair_trousers`, `man_bald_shorts`, `man_long_hair_jeans`, `man_ponytail_capri`, `woman_long_hair_midi_skirt`, `woman_short_hair_mini_skirt`, `woman_ponytail_trousers`, `woman_bun_maxi_skirt`, `woman_buzz_cut_shorts`, `woman_knee_skirt`, `person_flat_chest_long_trousers`, `person_full_chest_trousers`. The options are independent of each other, so any combination of chest, hair, garment and length is possible; the names are only labels.

**Tints**: `skin`, `hair`, `cloth-top` (shirt and sleeves), `cloth-bottom` (trousers or skirt), `shoe`. Hair length, garments and chest are shape options, so they are fixed per asset; colours are chosen by the game. A small set of presets plus tints gives a varied crowd.

**Animation**, from easiest:

1. **Baked frames**: `walker_<preset>_f0` ... `_f7` (category `frame`), one walk cycle, about 1 second per cycle (8 fps). The feet already stay on the ground.
2. **Rig**: groups `leg-near` (contains `shin-near`), `leg-far` (`shin-far`), `arm-near` (`forearm-near`), `arm-far` (`forearm-far`), `hair-back` (long hair, ponytail), `skirt`, `torso`, `head`. Pivots are in the manifest (`pivots`). With `walkPose` from `src/runtime/rig.ts`:

```ts
import { walkPose } from "./rig";
const rig = manifest["common/walker_woman_ponytail_trousers"].rig.walk;   // { thigh, shin, upperArm, foreArm }
function walk(t: number) {                       // t = 0..1, wraps
  const p = walkPose(t, rig);
  legNear.rotation = p.legNear.thigh;  shinNear.rotation = p.legNear.shin;     // degrees
  legFar.rotation = p.legFar.thigh;    shinFar.rotation = p.legFar.shin;
  armNear.rotation = p.armNear.arm;    forearmNear.rotation = p.armNear.fore;
  armFar.rotation = p.armFar.arm;      forearmFar.rotation = p.armFar.fore;
  hairBack.rotation = p.sway;  skirt.rotation = p.sway * 0.7;
  root.y = baseY + p.bodyDy;                     // keeps the lowest foot on the ground
}
```
Rotations are in SVG degrees (positive = clockwise, so the leg swings forward with a negative angle); convert to radians for PixiJS and rotate each group about its pivot. Child groups (shin, forearm) rotate in their parent's local frame around the base-pose pivot, so the manifest pivots apply as they are. Walking speed: scale the cycle rate with the ground speed (stride about 24 units).
3. Change `WALK` (amplitudes) in `src/runtime/rig.ts` for a different gait (run: larger `legAmp`, `knee`, `armAmp`, faster cycle).

Pedestrian ideas for Pontifex: people crossing the bridge as ambient life, passengers that fall when a bridge fails, a crowd per biome (tint palettes), a cyclist among them.

## Animation hooks

| asset | group | what to do |
|---|---|---|
| `wind_turbine`, `wind_turbine_small` | `rotor` | rotate around `pivots.rotor`; rotation speed = wind strength |
| `windmill` | `sails` | same |
| `drone` | `rotor-left`, `rotor-right` | spin or flicker |
| `flyingBird` assets (`gull`, `eagle`, `robo_bird`, `bird_swallow`, `bird_crow`) | `wing`, `wing-back` | flap: rotate `wing` about `pivots.wing`, +-25 deg |
| `steam_vent`, `smoking_vent`, `cooling_tower`, `volcano` | (static puff) | spawn smoke particles from MWG at the top |
| neon items (`cyberpunk`) | whole asset | pulse alpha of the asset; the glow is part of the SVG |
| `rain`, `aurora` | tile overlays | scroll or fade |

Perched birds (`pigeon`, `stork`, `vulture`, `toucan`, `bird_*_perched`) are static: swap them for a flying bird when the bridge shakes.

## Loading in Pontifex (PixiJS)

```ts
const m = await (await fetch("/art/biomes/manifest.json")).json();
const e = m["common/wind_turbine"];
const tex = await Assets.load(`/art/biomes/${e.file}`);   // SVG -> texture; set the resolution at load time
const s = new Sprite(tex);
s.anchor.set(...e.anchor);
// rotating part: load the group as its own sprite, or split the SVG once with DOMParser,
// then use pivots.rotor as the pivot of that child.
```

Hot path tip: rasterise each SVG once at the display scale (`Assets.load({ src, data: { resolution } })`) and reuse the texture; do not re-parse SVG per frame.

## Extending

1. Add an asset in `src/gen/biomes/{cities,nature,extras}.ts` with `add(biome, name, category, asset)`.
2. Recolourable parts: add `tint: "role"` to `shape()` options (see the roles table). Shared runtime helpers are in `src/runtime/` (`tint.ts`, `rig.ts`).
3. Helpers (`src/gen/biomes/common.ts`): `house()` (parametric building: wall, roof kind, window grid, door), `roundTree()`, `firTree()`, `boxVehicle()` (wheeled box vehicle), `flyingBird()`, `perchedBird()`, `hills()` and `skyline()` (seamless backgrounds), `glow()`; shape primitives in `src/gen/kit.ts` (`unite`, `subtract`, `circleD`, `symmetricD`, `turn`, ...).
4. `npm run gen:biomes`, then look at `sheet-<biome>.png`. Names must be unique per biome. Output is deterministic (seeded), so regenerating produces the same files.
5. For a fixed colour variant, call the same builder with another palette (see the tree seasons in `extras.ts`); for a game-side choice use tints.
6. Optional final pass: `optimize_svg` (svgo) on the files, once the shapes are final.

## Known limits / to do

- The base set keeps its original Pontifex conventions: clouds anchor `[0, 0]`, explosion `[0.5, 0.5]`, `hood`/`engine` groups on car and jeep, `fire-outer`/`fire-mid`/`fire-core` and `flame-outer`/`flame-core` groups.
- Vehicles shared by several biomes (`bicycle`, `cyclist`, `delivery_van`, `pickup_truck`) are in `common`; biome-flavoured ones stay in their biome (`vintage_car`, `tractor`, `snowplow`...). Move any asset by changing its `add()` biome.
- Walkers face right only (flip the sprite for the other direction), are adult proportions, and have no run, idle or fall animation yet. Skirts do not blow in the wind beyond the small sway.
- Not tested inside Pontifex yet: check pivots, anchors and the sizes against the game scale; adjust the `SHEET` table in `src/art.ts` from the manifest.
- Some cells are approximations: `stork` looks like a small wading bird, `statue` is a simple figure, `steam_vent` is a plain puff; they would benefit from a manual pass.
- Season variants exist only for `roundTree` (`common/tree_*`); other trees have one colour set.
- Background layers have no lighting variants (day only). A night version can be made by re-running `hills()`/`skyline()` with darker fills.
